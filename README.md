- Тесты: Vitest, Testcontainers, Playwright

## Установка

Нужны [mise](https://mise.jdx.dev/) (ставит Node и pnpm нужных версий из `mise.toml`) и Docker.

```bash
git clone https://github.com/Geschoss/ai-for-developers-project-386.git
cd ai-for-developers-project-386
mise install
pnpm install
```

`mise install` ставит git-хук pre-commit. Хук проверяет oxlint и формат только у файлов в индексе и ничего не исправляет.

Запуск всего приложения с базой — в Docker, на http://localhost:3000:

```bash
ADMIN_EMAIL=admin@example.com ADMIN_PASSWORD=придумайте-пароль docker compose up --build
```

Режим разработки: база в Docker, бэкенд и фронтенд с перезагрузкой, фронтенд на http://localhost:5173:

```bash
docker compose up -d db
cp .env.example backend/.env  # замените ADMIN_PASSWORD на свой
pnpm dev
```

### Администратор

Администратор один. Его создаёт старт приложения из переменных окружения `ADMIN_EMAIL` и `ADMIN_PASSWORD`, если
в базе Администратора ещё нет. Повторный старт второго не создаёт, даже если переменные изменились: пароль
существующего Администратора они тоже не меняют. Без любой из двух переменных приложение не стартует и пишет,
какой не хватает (`ADMIN_EMAIL is not set`). Если `ADMIN_EMAIL` уже занят Владельцем, старт тоже падает с ошибкой.

Учётные данные не коммитьте: в `.env.example` только заглушки. На проде задайте их в переменных окружения сервиса.

Публичный адрес: https://ai-for-developers-project-386-fo1o.onrender.com. На Render работают web service из
`Dockerfile` и Postgres, оба на бесплатном плане. Бесплатный Postgres живёт 30 дней. `ADMIN_EMAIL` и `ADMIN_PASSWORD`
задаются в переменных окружения сервиса в панели Render и в репозиторий не попадают.

На прод уходят только релизы. Когда релизный PR (`chore(main): release …`) смержен и `ci` на его коммите в `main`
зелёный, job `deploy` в `ci.yml` вызывает Deploy Hook сервиса с этим коммитом. Обычные PR в `main` не деплоятся.
Настройка один раз: в панели сервиса Settings → Auto-Deploy → Off, затем скопировать Deploy Hook из Settings и
сохранить его секретом репозитория командой `gh secret set RENDER_DEPLOY_HOOK_URL`. URL хука сам запускает деплой,
не коммитьте его.

### Render MCP

Подключение Cursor к Render. Файл `.cursor/mcp.json` берёт ключ из окружения (`RENDER_API_KEY`) и не содержит сам ключ.

1. Создайте ключ: https://dashboard.render.com/u/settings#api-keys
2. Экспортируйте его в окружение как `RENDER_API_KEY`. Ключ не коммитьте.
3. Перезапустите Cursor.
4. Проверьте подключение: запросите список сервисов Render.

Проверки качества кода: `mise run check` (oxlint, oxfmt, tsc, knip, dependency-cruiser, сверка контракта, тесты и e2e, по очереди). По отдельности: `mise run lint`, `format`, `fix`, `typecheck`, `knip`, `depcruise`, `spec`, `test`, `e2e`. Тестам нужен запущенный Docker. Браузер Playwright ставится один раз: `pnpm --filter e2e exec playwright install chromium`.

## Использование

Сервис для трёх ролей. Владелец регистрируется сам, Гость бронирует по ссылке без аккаунта, Администратор
только смотрит список Владельцев.

### Владелец

1. Откройте сайт и нажмите «Регистрация». Укажите имя, email, пароль, Адрес календаря
   (`a-z`, цифры и дефис, 3–30 символов) и часовой пояс.
2. После регистрации открываются «Предстоящие события». Пока Бронирований нет, список пуст.
3. В «Настройках» меняются часовой пояс, Горизонт планирования (1–60 дней, по умолчанию 14) и Лимит
   бронирований (1–18 на email за день, по умолчанию 2). Уже сделанные Бронирования при этом остаются.
4. «Скопировать ссылку» кладёт в буфер адрес текущего сайта: `/u/<адрес-календаря>`. Его и отправляют
   Гостю. «Мой календарь» открывает ту же страницу.
5. Когда Гость бронирует Слот, в «Предстоящих событиях» появляются его имя, email, время Слота в поясе
   Владельца и дата создания. Список идёт по времени начала. Слот, который уже начался, пропадает.

### Гость

1. Откройте ссылку Владельца, `/u/<адрес-календаря>`.
2. Выберите день в пределах горизонта и свободный Слот. Время показано в поясе браузера. Если он не
   совпадает с поясом Владельца, на странице есть плашка с временем Владельца.
3. Введите имя и email и нажмите «Забронировать». Аккаунт не нужен, письма не отправляются.
4. Экран «Вы записаны» показывает Владельца, дату и время в обоих поясах.
5. Занятый Слот второй Гость занять не может. Нельзя бронировать прошедший Слот, Слот за горизонтом и
   свой собственный календарь. Один email не может превысить Лимит бронирований за день в поясе Владельца.

### Администратор

1. Войдите email и паролем из `ADMIN_EMAIL` и `ADMIN_PASSWORD`. Регистрация Администратора не создаёт.
2. Открывается список Владельцев: имя, email, ссылка на календарь, часовой пояс и дата регистрации.
   Календаря у Администратора нет, и предстоящие Бронирования ему не показываются.
