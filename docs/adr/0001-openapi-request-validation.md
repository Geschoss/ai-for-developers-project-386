# Запросы валидируются по OpenAPI-спеке, а не через class-validator DTO

API-контракт пишется на TypeSpec и компилируется в `spec/openapi.yaml`. Этот файл — единственный источник правды
о форме запросов и ответов. В NestJS обычно описывают DTO с декораторами class-validator, но тогда та же схема
дублировалась бы вручную и со временем расходилась бы со спекой. Поэтому входящие запросы проверяет middleware
`express-openapi-validator` прямо по `openapi.yaml`. TS-типы генерируются из него же (`openapi-typescript`), общие
для бэкенда и фронтенда. Ответы сверяются со спекой в интеграционных тестах.

## Consequences

- Добавлять class-validator DTO «по привычке Nest» не нужно: валидация уже есть и живёт в спеке.
- Любое изменение API начинается с правки TypeSpec. CI проверяет, что закоммиченный `openapi.yaml` совпадает
  с результатом компиляции.
