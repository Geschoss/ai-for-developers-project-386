# Пересечение Бронирований закрывает exclusion-ограничение

Уникальный индекс `bookings (calendar_id, start_at)` запрещает два Бронирования с одним началом и пропускает
перекрытие разных начал: 10:00–11:00 и 10:30–11:00. Длительность берётся из Типа события и у разных типов
разная, поэтому совпадения начала больше недостаточно. Стык при этом допустим: запись с 11:00 после интервала
до 11:00 не пересекается.

Бронирование хранит `end_at`, посчитанный из длительности типа в момент записи. В той же транзакции, что и
вставка, после `SELECT … FOR UPDATE` строки Календаря, Postgres запрещает пересечение полуинтервалов
`[start_at, end_at)` одного Календаря exclusion-ограничением. Нарушение становится ошибкой `slot_taken`.
Проверка в агрегате остаётся: она объясняет отказ, а гонку двух запросов закрывает база.
