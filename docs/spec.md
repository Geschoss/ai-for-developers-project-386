# Спецификация: Календарь звонков

Итог дизайн-сессии от 2026-10-28. Термины — по [GLOSSARY.md](../GLOSSARY.md), обоснование неочевидных решений —
в [docs/adr/](./adr/). Визуальный референс — https://files.hexlet.app/a/2ipc5m (главная, «Запись на звонок»,
«Предстоящие события»).

## Роли

| Роль | Как появляется | Что может |
|---|---|---|
| **Владелец** | Только саморегистрацией | Настраивать свой календарь, видеть свои Бронирования, делиться ссылкой |
| **Гость** | Без аккаунта | Бронировать Слоты по публичной ссылке, указав имя и email |
| **Администратор** | Один. Создаётся при старте из `ADMIN_EMAIL` / `ADMIN_PASSWORD`, если его нет в БД | Смотреть список Владельцев (только чтение). Календаря нет |

## Скоуп

**Входит:** лендинг, регистрация, вход/выход, настройки Владельца, публичная страница бронирования, экран
подтверждения, список предстоящих Бронирований Владельца, страница Администратора со списком пользователей.

**Не входит:** отмена и перенос Бронирований, email-уведомления, подтверждение email, восстановление пароля,
настройка рабочих часов и длительности Слота, несколько типов встреч, публичный каталог Владельцев, действия
Администратора над пользователями.

## Правила домена

### Слоты
- Слот длится 30 минут. Сетка 09:00–18:00 (18 Слотов, последний 17:30–18:00) задаётся в часовом поясе Владельца,
  каждый день, включая выходные.
- Слоты вычисляются из правил и не хранятся. Хранятся только Бронирования.
- Слот, который уже начался или прошёл, бронировать нельзя.

### Горизонт планирования
- Целое число дней, по умолчанию 14, от 1 до 60. Настраивается Владельцем.
- Отсчёт идёт от «сегодня» в часовом поясе Владельца, сегодняшний день входит в горизонт.
- Если горизонт уменьшен, существующие Бронирования за новой границей остаются в силе.

### Лимит бронирований
- Считается на пару (email Гостя без учёта регистра, Владелец) за календарный день в поясе Владельца.
- По умолчанию 2, от 1 до 18. Настраивается Владельцем.
- Если лимит уменьшен, существующие Бронирования остаются в силе.

### Бронирование
- На один Слот у одного Владельца — не больше одного Бронирования. При гонке выигрывает первый, второй получает
  `slot_taken` (гарантия на уровне БД, ADR-0003).
- Поля: имя Гостя, email Гостя, момент начала (абсолютный, UTC), дата создания.
- Бронирование не связано с логином. Залогиненный пользователь на чужой странице бронирует как обычный Гость.
  Бронировать собственный календарь нельзя (`own_calendar`).
- После бронирования Гость видит экран «Вы записаны»: Владелец, дата, время в поясе Гостя и в поясе Владельца.
  Писем нет.

### Часовые пояса
- Владелец выбирает IANA-пояс при регистрации (по умолчанию из браузера) и может сменить его в настройках.
- Пояс Гостя определяется браузером. Слоты показываются во времени Гостя. Если пояса различаются, на экране
  есть плашка: пояс Гостя и соответствующее время у Владельца.
- Бронирования — абсолютные моменты: смена пояса Владельцем их не сдвигает.

### Аккаунты
- Регистрация: имя; email (уникальный, без учёта регистра); пароль (≥ 8 символов); Адрес календаря (уникальный,
  `[a-z0-9-]`, 3–30 символов); часовой пояс.
- Вход по email и паролю. Серверные сессии в БД, cookie HttpOnly/Secure/SameSite=Lax, пароли хешируются argon2.

## Экраны

| Путь | Кто | Содержимое |
|---|---|---|
| `/` | все | Лендинг, кнопки «Регистрация» и «Войти» |
| `/register`, `/login` | аноним | Формы |
| `/u/<slug>` | все | «Запись на звонок у <имя Владельца>»: месячный календарь в пределах горизонта со счётчиком свободных Слотов на день, статусы Слотов дня, форма «Имя + Email», плашка о часовых поясах |
| `/u/<slug>/done` (или состояние экрана) | Гость | «Вы записаны» |
| `/events` | Владелец | Предстоящие Бронирования своего календаря: имя, email, время, дата создания |
| `/settings` | Владелец | Часовой пояс, Горизонт планирования, Лимит бронирований |
| `/admin/users` | Администратор | Таблица Владельцев: имя, email, ссылка, пояс, дата регистрации |

Шапка: у Владельца — «Мой календарь» (с копированием ссылки для гостей), «Предстоящие события», «Настройки»,
«Выйти». У Администратора — «Пользователи», «Выйти». Гость видит только `/u/<slug>`. Список Бронирований
приватный: Гость видит лишь «Свободно» / «Занято».

## Ошибки API

RFC 9457 (`application/problem+json`) с машиночитаемым `code`. Фронтенд переводит `code` в русский текст.

| `code` | HTTP |
|---|---|
| `slot_taken` | 409 |
| `daily_limit_reached` | 409 |
| `slug_taken`, `email_taken` | 409 |
| `outside_planning_horizon` | 422 |
| `slot_in_past` | 422 |
| `own_calendar` | 422 |
| `invalid_credentials` | 401 |

## Техническое решение

- **Контракт:** TypeSpec в `spec/` → закоммиченный `spec/openapi.yaml`, единственный источник правды. Запросы
  валидирует `express-openapi-validator`, типы генерирует `openapi-typescript` (ADR-0001).
- **Бэкенд:** NestJS + TypeScript, Drizzle + PostgreSQL (ADR-0002).
- **Фронтенд:** React + TypeScript + Vite + Mantine, клиент `openapi-fetch`.
- **Репозиторий:** pnpm workspaces — `spec/`, `backend/`, `frontend/`, `e2e/`. Node 24 LTS.
- **Тесты:** Vitest везде (на бэкенде с `unplugin-swc`). Бэкенд: supertest + `@testcontainers/postgresql`
  + fast-check, ответы сверяются со спекой. Фронтенд: Testing Library. E2E: Playwright.
- **E2E-сценарии:** регистрация → настройки; Гость бронирует → Владелец видит Бронирование; конфликт двух Гостей;
  исчерпание лимита; Гость в другом поясе видит плашку; Администратор видит список.
- **Развёртывание:** один Docker-образ. Nest отдаёт `/api/*` и статику SPA с fallback на `index.html`. При старте
  выполняются миграции и создаётся Администратор. Локально — `docker compose` с Postgres.
- **CI/CD:** отдельный workflow GitHub Actions: lint, typecheck, проверка совпадения `openapi.yaml` с TypeSpec,
  тесты, E2E. Render (web service из Dockerfile + managed Postgres) деплоит `main` после зелёного CI, настройка
  через Render MCP. `hexlet-check.yml` не трогаем.
