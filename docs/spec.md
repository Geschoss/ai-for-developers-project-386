# Спецификация: Календарь звонков

Итог дизайн-сессии от 2026-10-28. Термины — по [GLOSSARY.md](../GLOSSARY.md), обоснование неочевидных решений —
в [docs/adr/](./adr/). Визуальный референс — скриншоты в [docs/reference/](./reference/) (главная, «Запись на звонок»,
подтверждение, «Предстоящие события»). Где спецификация расходится с референсом, права спецификация.

## Роли

| Роль              | Как появляется                                                                    | Что может                                                              |
| ----------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| **Владелец**      | Саморегистрация. Старт также создаёт демо-Владельца, если email и Адрес свободны  | Настраивать свой календарь, видеть свои Бронирования, делиться ссылкой |
| **Гость**         | Без аккаунта                                                                      | Бронировать Слоты по публичной ссылке, указав имя и email              |
| **Администратор** | Один. Создаётся при старте из `ADMIN_EMAIL` / `ADMIN_PASSWORD`, если его нет в БД | Смотреть список Владельцев (только чтение). Календаря нет              |

## Скоуп

**Входит:** лендинг, регистрация, вход/выход, настройки Владельца, публичная страница бронирования, экран
подтверждения, список предстоящих Бронирований Владельца, страница Администратора со списком пользователей.

**Не входит:** отмена и перенос Бронирований, email-уведомления, подтверждение email, восстановление пароля,
настройка рабочих часов, изменение и удаление Типа события, публичный каталог Владельцев, действия
Администратора над пользователями.

## Правила домена

### Тип события

- Владелец создаёт Тип события в «Настройках»: название (1–100 символов), описание (1–1000 символов) и
  длительность в минутах. Id — UUID, его выдаёт сервер. В форме сырой UUID не показывается. Изменить и удалить
  тип нельзя.
- Регистрация тип не создаёт. Календарь без типов показывает Гостю пустой список и не принимает бронь.
- Длительность от 30 до 540 включительно и кратна 30. Иначе `validation_failed`.

### Слоты

- Длительность Слота берётся из выбранного Типа события. Гость выбирает тип и видит Слоты только этого типа.
- Рабочие часы 09:00–18:00 в часовом поясе Календаря, каждый день, включая выходные. Шаг начал общий, 30 минут.
  Слот целиком умещается до 18:00: для 30 минут последнее начало 17:30, для 60 минут — 17:00.
- Слоты вычисляются из правил и не хранятся. Хранятся только Бронирования.
- Слот, который уже начался или прошёл, бронировать нельзя.

### Горизонт планирования

- Целое число дней, по умолчанию 14, от 1 до 60. Настраивается Владельцем.
- Отсчёт идёт от «сегодня» в часовом поясе Владельца, сегодняшний день входит в горизонт.
- Если горизонт уменьшен, существующие Бронирования за новой границей остаются в силе.

### Лимит бронирований

- Считается число Бронирований на пару (email Гостя без учёта регистра, Владелец) за календарный день в поясе
  Владельца, а не их суммарная длительность.
- По умолчанию 2, от 1 до 18. Настраивается Владельцем.
- Если лимит уменьшен, существующие Бронирования остаются в силе.

### Бронирование

- Интервалы Бронирований одного Календаря не пересекаются. Занятость — полуинтервал `[начало, начало +
  длительность)`. Стык допустим: 60 минут в 10:00 отклоняют 30 минут в 10:30 (`slot_taken`, на экране «Этот слот
  уже занят») и принимают начало в 11:00. При гонке выигрывает первый (ADR-0003, ADR-0009).
- Чужой для этого Календаря id типа — `event_type_not_found`.
- Поля: имя Гостя, email Гостя, Тип события, начало и конец (абсолютные, UTC), дата создания.
- Бронирование не связано с логином. Залогиненный пользователь на чужой странице бронирует как обычный Гость.
  Бронировать собственный календарь нельзя (`own_calendar`).
- После бронирования Гость видит экран «Вы записаны»: Владелец, дата, время в поясе Гостя и в поясе Владельца.
  Писем нет.

### Часовые пояса

- Владелец выбирает IANA-пояс при регистрации (по умолчанию из браузера) и может сменить его в настройках.
- Пояс Гостя определяется браузером. Слоты показываются во времени Гостя. Если пояса различаются, на экране
  есть плашка: пояс Гостя и соответствующее время у Владельца.
- Бронирования — абсолютные моменты: смена пояса Владельцем их не сдвигает.

### Аккаунты

- Регистрация: имя; email (уникальный, без учёта регистра); пароль (≥ 8 символов); Адрес календаря (уникальный,
  `[a-z0-9-]`, 3–30 символов); часовой пояс.
- Вход по email и паролю. Серверные сессии в БД, cookie HttpOnly/Secure/SameSite=Lax, пароли хешируются argon2.
- При старте, рядом с Администратором, создаётся демо-Владелец, если его email и Адрес свободны: имя «Демо»,
  email `demo@example.com`, пароль `demo-owner-1`, Адрес `demo`, пояс `Europe/Moscow`, горизонт 14 и один Тип
  события «Звонок» (описание «Короткий созвон на 30 минут», 30 минут). Id типа выдаёт сервер. Повторный старт
  учётку не перезаписывает. Занятый email или Адрес старт не роняют и второго такого Владельца не создают.

## Экраны

| Путь                                    | Кто           | Содержимое                                                                                                                                                                                                |
| --------------------------------------- | ------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`                                     | все           | Лендинг, кнопки «Регистрация» и «Войти»                                                                                                                                                                   |
| `/register`, `/login`                   | аноним        | Формы                                                                                                                                                                                                     |
| `/u/<slug>`                             | все           | «Запись на звонок у <имя Владельца>»: выбор Типа события, месячный календарь в пределах горизонта со счётчиком свободных Слотов на день, статусы Слотов дня, форма «Имя + Email», плашка о часовых поясах |
| `/u/<slug>/done` (или состояние экрана) | Гость         | «Вы записаны»                                                                                                                                                                                             |
| `/events`                               | Владелец      | Предстоящие Бронирования своего календаря: имя, email, название Типа события, время, дата создания                                                                                                        |
| `/settings`                             | Владелец      | Часовой пояс, Горизонт планирования, Лимит бронирований, создание Типа события                                                                                                                            |
| `/admin/users`                          | Администратор | Таблица Владельцев: имя, email, ссылка, пояс, дата регистрации                                                                                                                                            |

Шапка: у Владельца — «Мой календарь» (с копированием ссылки для гостей), «Предстоящие события», «Настройки»,
«Выйти». У Администратора — «Пользователи», «Выйти». Гость видит только `/u/<slug>`. Список Бронирований
приватный: Гость видит лишь «Свободно» / «Занято».

## Ошибки API

RFC 9457 (`application/problem+json`) с машиночитаемым `code`. Фронтенд переводит `code` в русский текст.

| `code`                                                                             | HTTP |
| ---------------------------------------------------------------------------------- | ---- |
| `slot_taken`                                                                       | 409  |
| `daily_limit_reached`                                                              | 409  |
| `slug_taken`, `email_taken`                                                        | 409  |
| `outside_planning_horizon`                                                         | 422  |
| `slot_in_past`                                                                     | 422  |
| `own_calendar`                                                                     | 422  |
| `invalid_credentials`                                                              | 401  |
| `not_a_slot_start` — момент не совпадает с началом Слота сетки                     | 422  |
| `validation_failed` — запрос не прошёл схему, в том числе неизвестный часовой пояс | 400  |
| `unauthenticated`                                                                  | 401  |
| `forbidden` — роль не подходит                                                     | 403  |
| `calendar_not_found`                                                               | 404  |
| `event_type_not_found` — id Типа события не принадлежит этому Календарю            | 404  |

## Техническое решение

- **Контракт:** TypeSpec в `spec/` → закоммиченный `spec/openapi.yaml`, единственный источник правды. Запросы
  валидирует `express-openapi-validator`, типы генерирует `openapi-typescript` (ADR-0001).
- **Бэкенд:** NestJS + TypeScript, Drizzle + PostgreSQL (ADR-0002).
- **Фронтенд:** React + TypeScript + Vite + Mantine, клиент `openapi-fetch`.
- **Репозиторий:** pnpm workspaces — `spec/`, `backend/`, `frontend/`, `e2e/`. Node 24 LTS.
- **Тесты:** Vitest везде (на бэкенде с `unplugin-swc`). Бэкенд: supertest, `@testcontainers/postgresql` и
  fast-check; ответы сверяются со спекой. Фронтенд: Testing Library. E2E: Playwright.
- **E2E-сценарии:** регистрация → настройки; Гость бронирует → Владелец видит Бронирование; конфликт двух Гостей;
  исчерпание лимита; Гость в другом поясе видит плашку; Администратор видит список; Гость бронирует демо-Календарь
  `/u/demo` → демо-Владелец видит Бронирование.
- **Развёртывание:** один Docker-образ. Nest отдаёт `/api/*` и статику SPA с fallback на `index.html`. При старте
  выполняются миграции, создаётся Администратор и, если email и Адрес свободны, демо-Владелец. Локально —
  `docker compose` с Postgres.
- **CI/CD:** отдельный workflow GitHub Actions: lint, typecheck, проверка совпадения `openapi.yaml` с TypeSpec,
  тесты, E2E. Render (web service из Dockerfile + managed Postgres) деплоит только смерженный релизный PR: после
  зелёного CI на коммите `chore(main): release …` в `main` job `deploy` вызывает Deploy Hook. `hexlet-check.yml` не трогаем.
